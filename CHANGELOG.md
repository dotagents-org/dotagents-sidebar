# Changelog

What changed in each release. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). Changes land in **Unreleased** as they are made; a release turns that section into its version and its notes.

## Unreleased

### Added

- **Joining a split by dragging asks the side.** A session dropped on another with Shift opens the same list as Split Session (Right, Down, Left or Up, the side used last first) and joins on that side; it used to go to the right always. Escape leaves it where it was.
- **Splits in four directions, with the kind you choose.** `Split Session...` asks which side (right, down, left or up; the last side used first), then what opens there (Claude Code, Codex or Terminal; the split session's kind first), so Enter, Enter repeats the last split. The amber button, the command palette, a pane's menu and a session's menu all open it. Splits nest, as in herdr: each split is two halves side by side or one over the other, the line between them can be dragged, and closing a pane gives its space to its neighbor. The layout is saved with the sessions; splits saved before it open side by side in equal parts.
- **A pane's menu.** Shift + right click on a pane opens VS Code's menu for it: `Split Session...`, Copy, Paste, and the session's Rename, Color, Restart and Close. The new setting `dotagentsSidebar.rightClickBehavior` says what a plain right click does: as the integrated terminal (the default), `copyPaste`, `paste`, or `menu`. `Split Session...` is in a session's menu in the list too.
- **The ChatGPT app from a ChatGPT account's mark.** In the accounts panel, every account's mark opens its Desktop app on Windows: Claude Desktop for a Claude account, the ChatGPT app for a ChatGPT one (the core's `desktop` action, which opens it since the core's ChatGPT app per profile).
- **Codex sessions.** The title bar opens a session with Claude Code, with Codex or with a terminal, one button each with its mark, in place of the `+`; a Codex session runs `codex`, with its mark in the list in the session's color; `Split Session...` offers the split session's agent first. A session has a `provider` field (`claude` when missing, so saved sessions keep opening). Codex picks its own conversation id, so the view matches each session to the first `rollout-*.jsonl` created after it in its folder under `$CODEX_HOME/sessions` and resumes it with `codex resume <id>`, also after a window reload. Codex also has its terminal profile. Shift+Enter sends Ctrl+J to Codex.
- **Logs in files:** the extension writes to `sidebar.log` and the host process to `host.log`, in `<stateDir>/logs/` on each side (`~/.config/dotagents/logs/`), in the core's format (its `docs/logs.md`): the errors the output channel showed, the host's start and stop with its Node and pid, a `node-pty` that didn't load, a session whose command couldn't start, and a crash. Tokens are masked before writing, and past 1 MB a file rolls over to `.1`. `dotagents logs` shows both sides.
- **Reorder by dragging.** Drag a session in the list, as the terminal panel's tabs work: it takes its whole split with it next to the split of the row you drop it on (after it dragging down, before it dragging up), is only reordered when dropped on a row of its own split, and goes to the end when dropped below the last row. A line shows where, the sessions that move are dimmed, the session you moved becomes the active one, Escape gives up the drag and the list scrolls near its edges. With Shift the session changes its split instead: dropped on a row it joins that row's split, dropped below the last row it leaves its split, alone at the end. The order is kept across window reloads, the panes of a split follow it, and the accounts tab stays first.
- **Terminal.** A terminal button next to the new-session one opens a session with your shell in the workspace folder, with its own icon in the list.
- **Terminal title.** A terminal session's title shows the folder its shell is in, as a path from `~` when it is in the home folder (`~/work/app/src`, the workspace's own folder included), or the whole path when it is elsewhere; on Windows it is the path as Windows shows it (`C:\Users\me\work`, with backslashes and no `~`); the folder you are in is highlighted, a long path is cut on the left, and the tooltip has the full path. Bash (through `shell/bash-cwd.sh`, which loads `~/.bashrc` first) and PowerShell report it at every prompt; other shells keep the folder the session started in.
- **Own icons.** Every button on the title bar and every dotagents mark share one geometry (the face's square, a 1.9 line, the whole box used): a prompt (`>_`) in place of the eyes for the terminal, Claude Code's and Codex's marks for a new session of each, a line down the middle for split, a green circular arrow for restart and a red cross for close, instead of the `+` that now read as "new anything".
- **File links.** File paths in a session are links, underlined under the mouse: a click opens the file at its line and column (`src/a.ts:41:7`, `(41,7)`, `", line 12"`), or a folder in the Explorer. Only paths that exist are links, tried from the sessions' folder and each workspace folder; a path with spaces needs double quotes. Links an agent marks itself (OSC 8) open too: web pages in the browser, `file://` in the editor.
- **Sessions:** several Claude Code sessions side by side, with splits like the terminal panel, a session list, and agents that keep running across window reloads (a detached host process).
- **Your Claude accounts, with [dotagents](https://github.com/dotagents-org/dotagents-core):** on a machine where dotagents has profiles, the list starts with a fixed *Accounts* tab: every account's usage, its state as an avatar, and a switch that puts it on both sides of the machine. The status bar shows the current account and its usage as in the statusLine; a click switches. The data comes from `dotagents start` (dotagents-core), which the view starts in the background when none answers.
- **Claude Code only, for now:** OpenCode and Codex are switched off; their support stays in the code.

### Changed

- **The seat on each card.** An account card says its plan and seat (`Team Standard`, `Team Premium`, `Business`), also with one provider, where there is no group header, so two seats of one plan are told apart. Refusing a core older than API 3, the view says to end the `dotagents start` it left running too.
- **ChatGPT accounts under `chatgpt`.** The accounts tab and the status bar read a ChatGPT profile's provider and the start API's `slots` and `current` as `chatgpt`, the account's name, as the core now says it; Codex sessions keep theirs. The view knows API version 3, and refuses an older core's answer saying which side to update.
- **What to do after a switch, as the core says it.** The switch list's notification and the accounts panel show the line `dotagents switch` ends with, from the core's answer (`next`): for Claude, open conversations go on after `continue`; for ChatGPT, Codex sessions already open keep the old account until you restart them. The notification had Claude's line written in the sidebar, and nothing for ChatGPT; the panel said nothing.
- **Plans by the product's name.** The accounts panel's group header says *Team  2 seats* for Claude and *Business  2 seats* for ChatGPT (Claude Team and ChatGPT Business, which was ChatGPT Team), where it said the API's `team` for both.
- **Claude and ChatGPT side by side.** In the accounts tab the windows' labels share one column across every card, so the bars of both providers line up, and a week's "projection from" says the day.

- **The buttons in the title strip.** The view's buttons moved from VS Code's title bar to the strip with the session's title and path. At its left, three round buttons act on the active session in the identity's level colors: red closes it, amber splits it, green restarts it, each showing its sign under the pointer. At its right, round too, a new Claude Code, Codex or terminal session. The strip shows over the accounts tab and an empty view too, with the new-session buttons only.
- **The focused pane has a line around it.** The pane the keys go to shows a rounded line in its session's color (the theme's focus border for a session without one), which goes away when the focus leaves the view, so in a split you see where you are typing.
- **Codex discovery.** Rollout reading and pending-session matching live together in a module separate from the agent launch table.

- **Session startup.** Agent and terminal sessions share the host creation message and dimmed notice formatting.

- **Shared account labels and marks.** The status bar, switch list and accounts panel use one provider table, keeping Claude and ChatGPT names and brand marks together. Session agents retain their Claude Code and Codex names.

- **Accounts per provider.** The status bar has a group for Claude and, only when there is a ChatGPT account, a second for ChatGPT, each led by its provider's mark (Claude, OpenAI) and showing its own current account; the items are named `Account`, and all share one priority so they stay together. The switch command lists the accounts of both providers, with the provider named, and switches the chosen one. A panel group's header says the plan with its seats (`team  2 seats`) when known. hopper (a hexagon) and dijkstra (an arch) have avatars of their own. The marks are new glyphs of `media/icons.woff`, written by `scripts/vscode-icon.py`.
- **The brands' own marks, from [LobeHub](https://lobehub.com/icons) (MIT):** Claude Code's sessions and their terminal tabs show the Claude Code mark (`media/claude-code-{light,dark}.svg`), and the button that opens an account's Claude Desktop keeps the Claude mark, the app's.
- **Accounts panel.** The panel opens straight on the cards: the `dotagents` seal, the profile count and the `Windows and WSL` line are gone (each card already says where its account is). The age of the numbers and the refresh sit on a line at the top, right-aligned; `WSL off` shows at its left, in the warning color, only when the other side is off.
- **Bigger avatars.** The accounts' avatars are 56 px, were 40, and the name, the gap beside them and the icon that opens the account's Desktop (21 px, were 15) scale with the avatar from one value, `--avatar` in `panel.css`, so the header of a card keeps its proportions if you change it.
- **Splits are drawn joined.** The sessions of a split are linked in the list by a line with a corner on the first, a branch on those between and a corner on the last, as the terminal panel's tabs do, instead of the same bar on each, so a split no longer looks like one session.
- **Focus after closing in a split.** Closing the active session inside a split keeps the focus in that split (on the session before it, else the one after), instead of jumping to the next session of another one.
- **Same size everywhere.** The session list and the title strip draw the marks at 16 px, the size VS Code gives its own title bar buttons and the view's icon at the top, and every mark uses the whole square, so they look the same size. The list's rows are taller (28 px, were 22) to keep them easy to click.
- **Aligned dividers.** The title strip and the accounts tab beside it are the same height, so the line under them is one line instead of two a couple of pixels apart.
- **Title strip.** The workspace (or a terminal's folder), the slash and the session's name sit together, with no gaps around the slash.
- **Session colors.** A new session takes a color no open session has, or the least used one, instead of the next in a fixed rotation that could repeat an open session's color after others closed.

### Fixed

- **Codex titles keep their punctuation and braille text.** The sidebar removes only the delimited spinner and recording marker at the start of the title, and compares the remaining project segment as written.

- **Terminals draw their letters at full size again.** Since VS Code 1.147, Chromium ignores a canvas font that starts with a space and falls back to 10px sans-serif; xterm's WebGL renderer sets such a font for its glyphs, so letters came out small and thin, spread apart in their cells. The view now trims that space, as VS Code does for its own terminal. `"dotagentsSidebar.renderer": "dom"` is the way around a rendering problem like this one until a fix comes.
- **The accounts start their server on Windows.** The extension started `dotagents start` through a detached PowerShell, which on Windows has no console and exits without running anything, so the accounts stayed on "Starting the dotagents server..." until it was started by hand.
- **The side and kind lists stay open while the agents work.** Every redraw of the view, even for a title or a folder that changed, focused the active terminal, which could close Split Session's lists (and Join Session's) before you picked. The terminal now takes the focus only when the session in view changes.
- **Split Session no longer misuses the list's `kind`.** The list of what to open passed the agent in the field VS Code reserves for separators (`QuickPickItemKind`); it worked only because VS Code ignored the unknown value.
- **A Codex session's title without the project.** Codex puts its items in the window title joined by ` | ` (the thread's name, then the project, in the order `tui.terminal_title` gives): the title strip keeps the thread's name and drops the last part when it is the name of the session's folder, whole or cut as Codex cuts it. Otherwise the title stays whole, since in another order that part may be the thread's own name.
- **Codex on Windows when scripts are blocked.** A session starts its agent as an application (`codex.exe`, or the `codex.cmd` npm installs), never the `codex.ps1` beside it, which PowerShell refuses where its execution policy blocks scripts.
- **The right conversation after /clear, /resume or two Codex sessions at once.** Each agent session starts with a `SessionStart` hook on its own command line (never in your settings) that writes the conversation it is in to the session's file in the extension's storage, and the view resumes that one. A Claude Code session resumed the conversation it started with even after `/clear` or `/resume`, and two Codex sessions started together in one folder could swap conversations. Codex runs the hook once you trust it (it asks once); until then the view still guesses from the rollouts, leaves out a subagent's, and opens Codex's own list of the folder's conversations instead of resuming a guess. Codex tells a new conversation only at its first message: a Codex session restarted right after `/clear` or `/resume`, before you send anything, still opens the conversation of before.
- **Switching an account already in use on one side.** The status bar's switch list now lets you pick the current account when another side still needs to switch to it.
- **Reloading the window no longer fails while letting go of the host.** The view's `dispose()` called a `dispose` its log didn't have, so it threw before closing the host's channel and left the output channel behind; the host's channel now closes first, then the log's.
- **Sessions after a window reload.** After Developer: Reload Window, only the session in view was drawn right; the others came back with wrapped, misplaced lines when opened. A pane that isn't showing can't be fitted, so its terminal was still 80x24 when the host's screen, drawn at the real size, was written into it. The host now sends each screen's size and the pane takes it before the screen is written; with a host from before that (it outlives an update), the pane takes the size of one that is showing.
- **Status bar parts kept together.** Another extension's item (a port, a line count) could land between the account and its usage bars, since each part had its own priority. They now share one, so VS Code keeps them side by side, in order.
- **Paste on Windows.** Ctrl+V sent a ^V before the text, which Claude Code on Windows reads as pasting an image, so the text never came. Now only the paste itself reaches the agent, as in the integrated terminal.
- **Copy and paste like the integrated terminal.** Ctrl+Shift+C copies and Ctrl+Shift+V pastes; a right click copies the selection or pastes, as `terminal.integrated.rightClickBehavior` says (`copyPaste` by default on Windows).
- **On Windows, `dotagents start` runs on its own.** The view used to start it tied to a console window, so closing that window, or VS Code, stopped the server and the accounts tab went back to *Starting*. It now starts it through a hidden `Start-Process`.

### Removed

- **`Split With Claude Code Session` and `Split With Codex Session`.** `Split Session...` asks what opens beside the session, Claude Code, Codex or Terminal.

- **The daily update check.** It looked for a newer GitHub release to install; with no release published, build the `.vsix` from the repository instead (Getting started).
- **OpenCode and the old Codex support.** Their support, switched off before, is gone from the code. There is no `⌄` provider menu (New Session With..., Split Session With): each agent has its own button.
